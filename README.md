# مهام التشغيل

سيستم متابعة مهام لشركة السياحة: المدير العام يبعت المهمة ← مدير التشغيل يوزعها على الموظف ← الموظف يشتغل ويكتب تحديثات ← المشرف يعتمد ويقفل.
المهمة بتفضل ظاهرة حسب الأولوية لحد ما مدير التشغيل يعتمد إغلاقها.

## الأدوار

| الدور | يقدر يعمل إيه |
|---|---|
| **مدير التشغيل** (إنت) | يشوف كل المهام، يضيف ويوزع ويحوّل، يغيّر الأولوية والميعاد، يوافق على طلبات مد الوقت، يعتمد الإغلاق ويقيّم، يضيف حسابات فريق العمل |
| **المدير العام** | يبعت مهام جديدة لمدير التشغيل، يشوف كل المهام وسجل المتابعة، يكتب ملاحظات |
| **الموظف** | يشوف المهام اللي عليه، يبدأ التنفيذ، يكتب تحديثات، يطلب مد الوقت، يحوّل جزء لزميل، يربط ملفات من الأرشيف، يبعت المهمة للاعتماد (مايقدرش يقفلها) |

## أرشيف الملفات
صفحة `archive.html` (زرار «رفع ملف للأرشيف» جوه أي مهمة). كل رفعة بتاخد رقم زي `A-0012`، والرقم ده بيتلصق في المهمة في خانة «المرفقات من الأرشيف».
الملفات بتتخزن في Firestore نفسه (مش محتاج خدمة تانية). أقصى حجم للملف ٦ ميجا، والصور بتتصغّر تلقائياً.

> **مهم:** كل ما ملف `firestore.rules` يتغير، لازم تنسخه تاني وتنشره من Firestore → Rules → Publish.

## خطوات التشغيل (مرة واحدة)

### ١. مشروع Firebase جديد
1. ادخل https://console.firebase.google.com واعمل **Add project** (مثلاً `tasks-ops`).
2. من **Build → Authentication → Get started** فعّل **Email/Password**.
3. من **Build → Firestore Database → Create database** (اختار Production mode وأقرب منطقة).
4. من **Firestore → Rules** امسح اللي موجود وحط محتوى ملف `firestore.rules` واضغط **Publish**.
5. من **Project settings (الترس) → General → Your apps** اضغط أيقونة الويب `</>`، سمّيه، وانسخ قيم `firebaseConfig`.

### ٢. حط الإعدادات في الملف
افتح `index.html` وعدّل الجزء ده في أول السكريبت:

```js
const FIREBASE_CONFIG = {
  apiKey: "…",
  authDomain: "….firebaseapp.com",
  projectId: "…",
  storageBucket: "…",
  messagingSenderId: "…",
  appId: "…"
};
const OWNER_EMAIL = "khaledalhadedy001@gmail.com";
```

> طول ما `apiKey` فيها `PASTE_API_KEY` الصفحة بتشتغل كنسخة تجريبية ببيانات أمثلة.
> لو غيّرت `OWNER_EMAIL` غيّره كمان في أول ملف `firestore.rules`.

### ٣. ريبو جديد على GitHub
1. اعمل ريبو جديد وارفع فيه الملفات كلها (`index.html` و`firestore.rules` و`README.md` وفولدر `.github`).
2. من **Settings → Pages → Build and deployment → Source** اختار **GitHub Actions**.
3. أي push على `main` هيعمل نشر تلقائي. اللينك هيظهر في **Actions** وفي **Settings → Pages**.
4. في Firebase: **Authentication → Settings → Authorized domains** ضيف دومين الموقع (`اسمك.github.io`).

### ٤. أول دخول
1. من **Authentication → Users → Add user** اعمل حساب بإيميلك (`OWNER_EMAIL`) وكلمة سر.
2. ادخل الموقع بالحساب ده — هيتعمل لك حساب مشرف تلقائياً.
3. من زرار **فريق العمل** ضيف حساب المدير وحسابات الموظفين، وابعت لكل واحد الإيميل وكلمة السر.

## مسار المهمة

`بانتظار التوزيع` ← `تم التوزيع` ← `جاري التنفيذ` ← `بانتظار الاعتماد` ← `مغلقة`

- المشرف يقدر يرجّع المهمة من «بانتظار الاعتماد» لـ«جاري التنفيذ» مع كتابة السبب.
- المشرف يقدر يعيد فتح مهمة مغلقة.
- كل حركة بتتسجل في **سجل المتابعة** باسم اللي عملها ووقتها.

## الحضور والانصراف
- **شاشة الكود** (`kiosk.html`): بتتفتح على جهاز ثابت في الشركة. الكود بيتغير كل ٣٠ ثانية. الأحسن تعمل لها حساب بدور «جهاز الحضور» من صفحة الفريق.
- الموظف بيصوّر الكود بكاميرا الموبايل (أو يكتبه في صفحة «الحضور»)، والسيستم بيتأكد من **الكود** و**الموقع** مع بعض قبل ما يسجّل.
- مدير التشغيل لازم يحدد **موقع الشركة** مرة واحدة من صفحة «الحضور» ← إعدادات الحضور وهو جوه الشركة.
- التقرير الشهري فيه أيام الحضور وإجمالي الساعات ومتوسط اليوم، والتفاصيل يوم بيوم، ونسخ لإكسل.
